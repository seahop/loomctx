Your agent needs the right 400 tokens, with receipts.

LoomCtx remembers everything your tools have said about a host, an IP, an account or a CVE, and when it was true. When an agent asks, LoomCtx answers with a small, cited, time-aware context pack that fits the token budget the agent gave it. Sources that disagree come first. The problem

Agents get nothing, or they get everything.

Security teams hold years of facts about the same things, spread across scanners, inventories, identity providers, DHCP logs and advisories. An agent asked about one host gets either a blank or a dump of rows. LoomCtx sits in between: “what do we know about web-01 that matters to Tuesday's alert, in under 800 tokens, with citations.”

How it works

The write path is greedy. The read path is stingy.

Take in everything with its provenance, enrich it in the background, then answer each read from cheap precomputed material, inside the budget the caller set.

Two front doors, one model

Structured claims become observations directly. Documents are stored verbatim, then mined for claims with character-level provenance. Retrieval never cares which door a fact came through.

Bitemporal from day one

Every fact records when it was true and when LoomCtx learned it. “Which host had 10.0.4.7 during the incident window?” is one query, and it returns laptop-17, not web-01, which held the lease until August 10.

The graph is the index, not the payload

Agents never query the graph. They ask a question with a budget and get a pack. A multi-hop question (“KEV CVEs on software this host runs”) is a single scoped ask.

Append-only, never silently wrong

Observations are never edited, only superseded, and corrections are recorded. Redaction suppresses history and never rewrites it. When LoomCtx didn't look at everything, the pack says so.

Malleable by construction

Register your own entity types and predicates per namespace, swap SQLite for Postgres, plug in your own enrichers. None of it needs a fork. The tutorial builds a vuln-management domain without touching core code.

Every derived fact is cited

Each pack item carries the observation ids behind it. A faithfulness check fails any answer that cites an id the model was never shown.

Write path

greedy
  1. One envelopekind: claim or kind: document via HTTP, batch NDJSON, Kafka, Fluent Bit, Vector or the Go gateway.
  2. Append an observationSubject, predicate, object, source, confidence, valid_from/valid_to and recorded_at. Idempotent on event_id.
  3. Enrich asynchronouslyChunk and embed documents, extract claims with an LLM, resolve entities (natural keys → aliases → embeddings → adjudication). Merges are reversible.
  4. PrecomputeA bitemporal graph with time-bounded edges, plus cited per-entity dossiers so reads stay cheap.

Read path

stingy
  1. Resolve the scopeOne subject, or a bounded walk over containment and relation edges. Hub entities are never silently sampled.
  2. RankBM25 and embedding similarity fused by reciprocal rank, weighted by recency and source confidence.
  3. Conflicts firstWhen independent sources disagree on the same instant, that disagreement leads the pack. LoomCtx never picks a side silently.
  4. Pack to budgetValue-per-token selection up to the budget. Every item is cited. What didn't fit becomes a signed expansion handle, and charged_tokens reports what was spent.

  1. 1
    Time travel on every readvalid_at asks what was true at a moment. as_of asks what LoomCtx knew at a moment. Incident timelines get both.
  2. 2
    The budget is mandatoryThere is no read without one. Small budgets get the densest facts. LoomCtx packs by value per token, not by position.
  3. 3
    Typed itemsbrief, fact, relation, doc_excerpt or conflict. Conflicts ship first, so the agent sees a disagreement before anything else.
  4. 4
    Citations on everythingEvery item points at the observations behind it, with source and time. GET /v1/observations/{id}/prov exports W3C PROV-O.
  5. 5
    Expansion handlesWhat didn't fit becomes a stateless, HMAC-signed handle with a token estimate. The agent calls expand to pull one thread deeper.
  6. 6
    Honest truncationIf LoomCtx stopped gathering before it saw everything, the pack says how much it read. An agent never mistakes a partial read for a full one.
  7. 7
    What it actually costcharged_tokens is what the pack spent, always within the budget. A lease lookup with a budget of 600 cost 60.
One store, both sides of the line

Blue asks what happened. Red asks what's reachable.

Blue team

SOC · IR · vuln management · detection engineering
  • Which host held 10.0.4.7 on August 20th?A bitemporal read over DHCP leases. The answer is cited to dhcp-log, not guessed from the current state.
  • Which KEV-listed CVEs affect software web-01 runs?A scope walk from host → software → CVE, filtered by CISA KEV and scored with EPSS, delivered as one pack.
  • Is CVE-2026-0544 a 9.8 or a 5.5?NIST and the CNA disagree. LoomCtx puts that disagreement first and cites both, rather than quietly picking one.

Red team

pentest · adversary emulation · attack-path analysis
  • What can this account reach?find_path walks group membership → ACE → trust from raw LDAP/LDIF, Entra ID and Okta exports. Every hop is cited, and disabled accounts are flagged on the path.
  • Which exposed services run exploitable versions?nmap service fingerprints joined to NVD, OSV and KEV through cross-vendor product resolution.
  • What's in the cloud estate, and what does it connect to?Terraform state or an AWS Config snapshot, read into the same graph as the scans and identities.

Both teams use the same engine and the same packs. Each API key is scoped by namespace, read/write, entity type, source and expiry, so an engagement's data stays inside that engagement.

Where it fits

Not another vector database.

LoomCtx doesn't replace your SIEM, your graph or your RAG pipeline. It's the layer that decides what an agent actually gets to read.

Scorecard 1 · Core tasks on real vulnerability data

2-hop exposure“Is web-01 exposed to anything CISA lists as exploited in the wild?” The agent finds the host, walks host → software → CVE, and must name at least 16 of the 32 KEV CVEs with the software each affects. Naming a non-KEV CVE as part of the exposure fails.
Lease“Which host held 10.0.4.7 on 2026-08-20?” A time-travel read. The answer must name laptop-17 and must not present web-01, the earlier holder, as the answer.
Conflict“What do sources disagree about for CVE-2026-0544's CVSS?” The agent must report both values, 9.8 from NIST and 5.5 from the CNA.
OS“What OS does web-01 run?” Two sources disagree. The agent must give both values, not pick one.

Every task also has to be faithful: it must cite at least one observation the model was shown in that run, cite nothing it wasn't shown, and name no CVE that doesn't exist. A correct answer with no citation fails.

Named queries, on and off

A named query is a prepared question a connector ships with the schema. The LDAP connector registers seven, such as enabled_members, account_groups, kerberoastable_users and unconstrained_delegation_hosts. An agent runs one in a single call and gets exact, cited rows back:

run_query("enabled_members", group="Domain Admins")

Without them, the agent builds the same answer itself, for instance with a list call that walks member_of into the group and filters on enabled, or with a scoped ask. Every other tool is the same.

"Named queries off" is the same engine, data and models with run_query hidden (LOOMCTX_MCP_QUERIES=0). It measures what the prepared queries add over the agent composing its own calls. The headline numbers use the default, on.

Cross-domain admins“Which dev.local accounts are effective members of Domain Admins in corp.local, and is each enabled?” Five are, up to three groups deep; one is disabled and must be called out.
Coverage“Which groups is lab.local's labsvc-backup in?” That export never collected membership. The right answer says so; a confident “none” or a guessed group fails.
Nested groupsA membership report for one account: five groups, the last four levels up. A group nested into one of its groups, and a sibling group, must not be listed.
Delegation“Which non-DC computers are trusted for unconstrained delegation?” Three servers among the computers; the domain controllers and a constrained-delegation server are distractors.
TrustsEvery trust corp.local has, with its direction, whether it's transitive and whether SID filtering is on. One partner is non-transitive, one quarantined.
Access harder“Which Domain Admins have rights over workstation WS-AUDIT01, and through what?” One through a group holding GenericAll, one through a direct WriteDacl grant. An operator who isn't an admin, and an admin with no grant, are decoys.
Local admin harder“Who is local administrator on WS-AUDIT01?” Local group membership isn't in an AD export. Saying so passes; presenting accounts as its local admins fails.
Kerberoastable admins harder“Which enabled Domain Admins, nested included, are Kerberoastable?” One nested admin has an SPN. A disabled admin with one, and a service account that isn't an admin, are decoys.

Connectors

Speaks the formats you already export.

Connectors parse files you already have. They don't scan anything or call your cloud APIs. The one exception is the vulnerability connector, which pulls public feeds in one command with no API keys.

vulns vulnCISA KEV, NVD, EPSS and CISA Vulnrichment, with cross-scorer CVSS conflicts kept.
osv vulnOSV, GHSA, PYSEC, Go and npm advisories, fused to CVEs by alias.
nmap scannmap -oX reports: hosts, ports, services, software, OS guesses.
ldap identityRaw LDAP / LDIF from Active Directory: membership → ACE → trust reachability.
entra identityEntra ID Graph export: users, groups, service principals, roles, OAuth consents.
okta identityUsers, groups, apps, MFA and admin roles, in the same iam namespace as Entra.
cloud inventoryterraform show -json, tfstate, or an AWS Config snapshot.
ocsf detectionsOCSF vulnerability, detection, security and incident findings, both in and out.
stix threat intelSTIX 2.1 import and export.
attack taxonomyThe MITRE ATT&CK bundle as a shared catalog of techniques.

Deploy

One container on a laptop. The same contract at cluster scale.

The one-container shape

agent→loomctx · SQLite

Run docker compose up loomctx to get one engine and one SQLite file with vector search. No queue, and the LLM is optional. This is enough for an engagement laptop or a demo.

The scale shape

shippers→ Go gateway ×2–10→ NATS JetStream R=3→ writers→ Postgres + pgvector (HA)

Stateless engines autoscale from 2 to 8, with enrichment workers as a StatefulSet. Kubernetes manifests ship in four shapes: default, scale, scale-pg and scale-pg-ha. Validated on GKE.

  • Scoped API keys: stored hashed, hot-reloaded, and scoped by namespace, r/w, entity type, source and expiry
  • Signed handles: HMAC-SHA256, so expansion handles can't be forged or altered
  • Rate limits per grant, with a stricter bucket for LLM calls and Retry-After
  • Default-deny NetworkPolicies, PDBs, read-only root filesystem, non-root user
  • Supply chain: digest-pinned images, SHA-pinned actions, Trivy gate, SBOM and provenance
  • Data lifecycle: tombstone redaction, retention purge, JSONL export and migration
  • Bring any model: OpenRouter, Anthropic, OpenAI, Groq, Venice, or self-hosted Ollama / vLLM
  • 1,083 tests, run on SQLite and on a Postgres lane, plus a scale-shape smoke test in CI
Run it

Five minutes, Docker only.

Nothing installs on your host. The seed dataset includes the moments shown on this page: the reassigned IP lease, the OS conflict on web-01, and a disputed contract owner.

docker compose up -d --wait loomctx

  "question": "which host was assigned this ip?",
  "budget": 600
}'
